# Documentation Guidelines for Agentic Coding Systems
VERSION: 1.0
CREATED: 2025-11-20
PURPOSE: Define strict documentation standards for clarity, efficiency, and noise reduction

## 1. Documentation Philosophy

### Core Principles
1. **Single Source of Truth**: Each piece of information exists in exactly one authoritative location
2. **Just-In-Time Documentation**: Document only what's needed, when it's needed
3. **Living Documentation**: Docs evolve with code - no orphaned documentation
4. **Context Separation**: Clear boundary between working context and reference documentation
5. **Aggressive Archival**: If unused for 7+ days, archive it

### Anti-Patterns to Avoid
- ❌ Duplicate information across multiple files
- ❌ Brainstorm/research files in main directories
- ❌ Version numbers in filenames (use git)
- ❌ TODO comments in documentation
- ❌ Placeholder or template content
- ❌ Meeting notes or temporary artifacts

## 2. Directory Structure

### /context/ - Working Context (Dynamic)
```
context/
├── CLAUDE_PROCESS.md    # Process definition
├── conventions.md       # Coding & design standards
├── requirements.md      # Current requirements & specs
├── todo.md             # Active task tracking
├── planning.md         # Current sprint/phase planning
├── event-stream.md     # Execution log
└── doc-ref.md          # Documentation index
```

**Purpose**: Live, frequently-updated files that guide daily work
**Update Frequency**: Multiple times per day
**Retention**: Current version only (use git for history)

### /docs/ - Reference Documentation (Stable)
```
docs/
├── architecture/
│   └── system-design.md       # Core architecture decisions
├── api/
│   └── endpoints.md           # API specifications
├── deployment/
│   └── production-guide.md    # Deployment procedures
├── user-guide/
│   └── manual.md             # End-user documentation
└── changelog.md              # Version history
```

**Purpose**: Stable reference documentation
**Update Frequency**: Only with significant changes
**Retention**: Current version + major milestones

### /archive/ - Historical Records (Frozen)
```
archive/YYYY-MM-DD/
├── category/
│   └── archived-file.md
└── README.md              # Archive manifest
```

**Purpose**: Superseded documents for historical reference
**Update Frequency**: Never (read-only)
**Retention**: Compressed after 30 days

## 3. Documentation Lifecycle

### 3.1 Creation Phase
```mermaid
Start → Determine Category → Create in Correct Location → Update doc-ref.md
```

**Rules**:
- Start with clear purpose statement
- Use ISO date prefix: YYYY-MM-DD-name.md
- Maximum 500 lines per document
- Include VERSION and LAST-UPDATED headers

### 3.2 Active Phase
```mermaid
Update Content → Update Version → Log in event-stream → Sync doc-ref
```

**Rules**:
- Updates in same commit as related code
- Increment version for significant changes
- Keep changelog within document
- Link to related artifacts

### 3.3 Archive Phase
```mermaid
7 Days Unused → Move to /archive/YYYY-MM-DD/ → Update doc-ref → Add to .gitignore
```

**Triggers for Archival**:
- Document superseded by newer version
- Feature deprecated or removed
- 7+ days without reference
- Project phase completed

### 3.4 Deletion Phase
```mermaid
30 Days in Archive → Compress → 90 Days → Delete
```

**Permanent Deletion Criteria**:
- No historical value
- No compliance requirements
- No active references
- Archived for 90+ days

## 5. Documentation Standards

### 5.1 Writing Style
- **Tense**: Present tense for current state, future for plans
- **Voice**: Active voice, second person for instructions
- **Brevity**: Maximum 3 sentences per paragraph
- **Clarity**: Define acronyms on first use
- **Examples**: Include code examples for technical docs

### 5.2 Formatting Rules
- **Headers**: Maximum 3 levels (# ## ###)
- **Lists**: Use bullets for unordered, numbers for sequences
- **Code**: Use fenced blocks with language hints
- **Tables**: For comparisons and structured data
- **Links**: Relative paths within repo, full URLs external

### 5.3 Metadata Requirements
Every document MUST include:
```markdown
VERSION: X.Y
LAST-UPDATED: YYYY-MM-DD
PURPOSE: [One line description]
STATUS: DRAFT|ACTIVE|ARCHIVED
```

### 5.4 Naming Conventions
- **Context files**: lowercase, no dates (todo.md, planning.md)
- **Reference docs**: YYYY-MM-DD-descriptive-name.md
- **Archives**: Original name preserved in dated folder
- **No spaces**: Use hyphens for word separation

## 6. Quality Checklist

Before creating/updating documentation, verify:

- [ ] Is this the ONLY place this information exists?
- [ ] Does this belong in context/ or docs/?
- [ ] Is there an existing doc that should be updated instead?
- [ ] Have I removed all TODOs and placeholders?
- [ ] Is the document under 500 lines?
- [ ] Have I updated doc-ref.md?
- [ ] Have I checked for documents to archive?

## 7. Archival Process

### Weekly Cleanup (Automated)
```bash
# Find unused docs (7+ days)
find docs/ -type f -mtime +7 -name "*.md" | while read file; do
  # Check if referenced
  if ! grep -r "$(basename $file)" context/; then
    # Move to archive
    mkdir -p "archive/$(date +%Y-%m-%d)"
    mv "$file" "archive/$(date +%Y-%m-%d)/"
  fi
done
```

### Archive Structure
```
archive/
├── 2025-11-20/
│   ├── README.md        # Manifest of archived files
│   ├── research/        # Old research docs
│   ├── brainstorm/      # Old brainstorm sessions
│   └── implementation/  # Superseded implementations
└── .gitignore          # Ignore all archive contents
```
